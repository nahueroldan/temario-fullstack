2. JavaScript y TypeScript

El tema más repetido. Para nivel Senior tenés que predecir la salida de un código y explicar el porqué.

Temario

Preguntas típicas

¿Qué imprime: log(1); setTimeout(log 2, 0); Promise.then(log 3); log(4)?

1, 4, 3, 2. Primero lo síncrono, luego las microtareas y al final las macrotareas.

¿Diferencia entre var, let y const?

Scope de función vs de bloque, hoisting con y sin TDZ. const no vuelve inmutable al objeto, solo la referencia.

¿Qué es un closure y para qué sirve?

Una función que recuerda el scope donde se creó. Sirve para estado privado, factories, debounce y memoización.

¿Cómo funciona this en una arrow function?

No tiene this propio; lo toma del scope léxico donde se definió.

¿Promise.all vs Promise.allSettled?

all falla rápido ante el primer rechazo; allSettled espera a todas y devuelve el estado de cada una.

¿Cómo evitás una fuga de memoria en el front?

Limpiar listeners, timers y suscripciones; evitar referencias retenidas en closures y cachés sin límite.

¿unknown vs any?

any apaga el chequeo de tipos; unknown obliga a verificar el tipo antes de usar el valor.

Ejercicio: escribí a mano DeepPartial<T>, un Pick propio y un groupBy<T, K extends keyof T>.

3. React y Next.js

Se espera profundidad: por qué se re-renderiza algo y cómo lo optimizás.

Temario

Preguntas típicas

¿Cómo funciona el virtual DOM y por qué importa la key?

React compara dos árboles y aplica solo la diferencia. La key estable identifica elementos entre renders; con índices se pierde estado al reordenar.

¿useMemo vs useCallback?

useMemo memoiza un valor, useCallback una función. Solo ayudan si el hijo está en memo o el cálculo es costoso.

¿Por qué un useEffect corre en loop?

Dependencias que cambian en cada render (objetos o funciones inline) o un setState dentro del efecto sin condición.

¿Qué problema tiene Context para estado que cambia seguido?

Todos los consumidores se re-renderizan. Se mitiga dividiendo contextos o usando un store con selectores.

¿Server Component vs Client Component?

El server component corre solo en el servidor, no manda su JS al cliente y no puede usar estado ni efectos. El client component hidrata e interactúa.

¿SSR vs SSG vs ISR?

SSR renderiza en cada request, SSG en build, ISR en build con revalidación periódica.

¿Cómo mejorás una app React lenta?

Medir primero (Profiler, Lighthouse); luego dividir bundles, virtualizar listas, evitar re-renders y mover lógica al servidor.

¿Estado de servidor vs estado de cliente?

El de servidor es caché de datos remotos (React Query, SWR) con invalidación; el de cliente es UI (modales, filtros). Mezclarlos en Redux complica el código.

5. Backend con Node.js

¿Cómo funciona el event loop de Node y qué lo bloquea?

Un solo hilo ejecuta JavaScript y delega I/O al sistema. Lo bloquean cálculos pesados síncronos, JSON.parse de payloads enormes o bucles largos. Se resuelve con workers, streams o sacando ese trabajo a una cola.

¿Cómo organizás un proyecto NestJS?

Módulos por dominio, controladores finos, servicios con la lógica, repositorios para datos, DTOs validados y providers inyectados. Los guards manejan autorización y los interceptors el logging o la transformación de respuestas.

¿Cómo evitás procesar dos veces la misma operación?

Clave de idempotencia enviada por el cliente, guardada junto al resultado; el segundo intento devuelve el resultado ya calculado.

6. Java y Spring Boot

Frecuente en bancos, fintech y consultoras. Apuntá a poder defender lo que pongas en tu CV.

¿Cómo funciona la inyección de dependencias en Spring?

El contenedor crea los beans y los inyecta por constructor (lo recomendado), setter o campo. Esto desacopla las clases y facilita testear con mocks.

¿Qué es el problema N+1 en JPA y cómo se evita?

Una consulta trae la lista y luego se dispara una más por cada elemento al acceder a una relación lazy. Se evita con JOIN FETCH, @EntityGraph o consultas con proyecciones.

¿Qué hace @Transactional y qué trampa tiene?

Abre una transacción alrededor del método y hace rollback ante excepciones no controladas (por defecto, las unchecked). Trampa: no funciona si se llama a otro método de la misma clase, porque se saltea el proxy.

7. Bases de datos

¿Cuándo un índice no ayuda?

Con tablas chicas, columnas de baja selectividad, funciones aplicadas sobre la columna en el WHERE o cuando el orden de un índice compuesto no coincide con la consulta. Además, cada índice encarece las escrituras.

¿Qué son los niveles de aislamiento?

Definen qué anomalías permite una transacción: lectura sucia, no repetible o fantasma. Read committed es el valor habitual; serializable es el más estricto y el más costoso.

¿Offset o cursor para paginar?

Offset es simple pero se vuelve lento y inconsistente en tablas grandes con cambios. El cursor usa la última clave vista y escala mejor.

8. APIs, autenticación y seguridad

¿PUT vs PATCH?

PUT reemplaza el recurso completo; PATCH lo modifica parcialmente. Ambos deberían ser idempotentes si están bien diseñados.

¿Dónde guardás un JWT en el front?

Una cookie HttpOnly reduce el riesgo de XSS; localStorage es accesible por JavaScript y más expuesto. Se mitiga con CSP y tokens de vida corta.

¿Qué es CORS y por qué existe?

Es una restricción del navegador sobre pedidos entre orígenes. El servidor decide qué orígenes y headers permite. No protege al servidor, protege al usuario en el navegador.

¿REST o GraphQL?

GraphQL evita el over-fetching y reduce viajes, pero complica caché, autorización y monitoreo. REST es simple y cacheable por HTTP.

¿Cómo evitás cobros o transferencias duplicadas?

Claves de idempotencia, reintentos seguros y confirmación por el servidor (relevante en fintech y bancos).

9. Testing, CI/CD y observabilidad

¿Qué testeás con unitarios y qué con E2E?

Unitarios para lógica y componentes aislados; E2E para flujos críticos (login, pago). Pocos E2E, bien elegidos.

¿Qué hacés cuando un deploy rompe producción?

Mitigar primero (rollback o feature flag), comunicar, y después analizar la causa raíz y agregar un test o alerta.

¿Cómo diseñás un pipeline de CI/CD?

Etapas rápidas primero (lint, unitarios), luego build y E2E, con caché, ambientes y un deploy con rollback sencillo.

10. Arquitectura y system design fullstack

Para Senior es probable una ronda de diseño o preguntas de trade-offs. Usá siempre este marco.

  1. Requisitos funcionales y no funcionales (usuarios, latencia, disponibilidad, dispositivos).
  2. Alcance y supuestos: qué entra y qué no.
  3. Arquitectura general: cliente, API, base de datos, caché, colas.
  4. Modelo de datos y contratos de API.
  5. Frontend: componentes, estado, renderizado, manejo de errores y carga.
  6. Backend: servicios, transacciones, idempotencia, trabajos asíncronos.
  7. Rendimiento y escala: CDN, caché, índices, paginación, balanceo, rate limiting.
  8. Seguridad, testing y observabilidad.
  9. Trade-offs: nombrá una alternativa descartada y por qué.

Semana 2: React, Next.js y componentes en vivo

Semana 3: Backend, bases de datos y algoritmos

Semana 4: System design, charla y simulacros
